Tasks & Light Projects
Module

A lightweight, fast, multi-view task and project management module for Jiganto — inspired by the simplicity of Plutio Projects. Built for individuals, small teams and anyone who needs to manage work without the full Gantt chart complexity.

What Replit needs to build
A single-page Tasks & Light Projects module that feels fast and simple. The default view is a grouped table (grouped by Status). Users can switch to Kanban, Timeline (mini-Gantt), Calendar, or Board view from a dropdown in the toolbar. Every task row is inline-editable. Users can add their own columns from a predefined set of field types. The module is suitable for one person or a whole team — solo freelancers up to small company departments.
Overview

Core concept & guiding principles

Four design principles govern every decision in this module. If a feature conflicts with one of these, the principle wins.

⚡
Fast by default
Adding a task should take 2 seconds. Press Enter at the end of a row to create the next one. No modals, no mandatory fields beyond the task name.
🔄
Any view, one click
The same dataset is displayed across five views. Switching never loses data or state. The user's last-used view is remembered.
🧩
Flexible structure
The default columns work for 80% of use cases. Users can add their own columns (up to 10 custom fields) without IT help or configuration files.
👥
One or many
Works identically for a solo freelancer managing personal tasks or a 20-person team tracking a client project. No forced team setup required.
Navigation

Where it lives & how users get there

The module has two entry points in Jiganto and two working modes.

📋
Standalone Tasks — Personal & Team Task Lists
Accessed from the sidebar under Portfolio → Tasks. Holds any task that isn't tied to a specific project. Includes My Tasks (only the logged-in user's tasks) and All Tasks (all team members' tasks visible to the user).
  • Personal to-do lists — no client or project required
  • Team task board — assign work to colleagues
  • Recurring tasks — daily, weekly, monthly auto-creation
  • Filter by owner to see only your tasks or someone else's
📁
Project Tasks — Attached to a Light Project
Accessed from inside a project (Portfolio → Tasks → Project name). Tasks are scoped to one project and can be shared with a client. The project acts as a container — it has a name, status, client, members and due date at the top.
  • Project header: name, status badge, client, members, dates
  • All tasks beneath belong to this project only
  • Client users can log in and see only their project's tasks
  • Can optionally be promoted to a full Gantt project later

Status system

Six built-in statuses — colour-coded by default

These are the default statuses visible in the Plutio screenshot. Each status has a defined colour, label, and behaviour. Users can rename them or add custom statuses.

New
Task created but not yet started. Default for all new tasks.
In Progress
Actively being worked on. Counts in utilisation metrics.
Pending
Waiting on something or someone before it can proceed.
Delayed
Behind schedule. Can trigger a RAG red indicator if linked to dates.
Completed
Done. Moves to archived section after 7 days (configurable).
Cancelled
Dropped. Excluded from all progress calculations.

Custom columns

User-defined columns — the flexibility layer

Any user with edit access can add custom columns. Up to 10 custom columns per project or task list. These are the available field types Replit must implement.

🔤
Text
Free-text single-line input. Editable inline. Used for URLs, reference numbers, notes summaries, external IDs.
  • Inline edit on click
  • Optional URL validation (auto-link)
  • Max 255 characters
📝
Long Text / Notes
Multi-line text area. Not shown inline — opens as an expanded cell or in the task detail panel. Supports basic markdown.
  • Expand to full-width textarea on click
  • Preview first 80 chars in column
  • Markdown: bold, italic, bullet lists
🔢
Number
Integer or decimal numeric value. Supports optional currency prefix/suffix (£, $, %, hrs). Column footer shows sum or average.
  • Number format: integer, decimal, currency, percentage
  • Optional prefix/suffix symbol
  • Column sum shown in footer
📅
Date
A secondary date field (e.g. Start Date, Review Date, Invoice Date). Opens a date picker inline. Distinct from the built-in Due Date column.
  • Date only, or date + time
  • Overdue highlight in red
  • Usable in Timeline view as start date
☑
Checkbox
A true/false toggle. Shown as a checkbox in the row. One-click to toggle. Useful for approval flags, sign-off gates, or boolean conditions.
  • Click to toggle checked/unchecked
  • Filterable: show only checked or unchecked
  • Can be used to drive conditional formatting
🔽
Dropdown (Select)
Single-select from a user-defined list of options. When creating the column, the user defines the option labels and colours. Displayed as a coloured badge.
  • User defines options and their colours
  • Options editable after column creation
  • Shown as colour badge in row
  • Used as grouping/filtering key
🔽🔽
Multi-Select
Multiple options can be selected simultaneously. Shown as stacked colour pills in the row. User defines the option list when creating the column.
  • Multiple values per cell
  • Filter: show tasks with any/all selected values
  • Shown as multiple small pills
👤
Person
Links to a team member (same member list as the Members column). Useful for specific roles: Reviewer, Approver, Account Manager. Shows avatar + name.
  • Single person selection
  • Drawn from workspace member list
  • Filter by person across tasks
⭐
Rating
A 1–5 star rating. Shown as filled/empty stars. Useful for priority scoring, effort estimation, or client satisfaction tracking.
  • Click to set rating 1–5
  • Column average shown in footer
  • Sortable by star count
🔗
URL / Link
A URL field with optional label. Renders as a clickable link in the row. Opens in a new tab. Used for external resources, Figma links, documentation.
  • Validates URL format on entry
  • Shows as truncated link text
  • Optional display label (overrides URL text)
Custom column creation

How users add a column — step by step

This is the UX flow Replit must implement for adding a custom column. It must be accessible from the ＋ button at the end of the column header row.

① Click ＋
Trigger the column picker
A ＋ button sits at the end of the column header row (rightmost position). Clicking it opens a compact panel or dropdown listing all available field types in a 2×5 grid of icon cards.
② Select type
Choose a field type
User clicks one of the 10 field type cards. The panel updates to show the configuration form for that type — at minimum: Column Name. For dropdowns: option list. For numbers: format.
③ Configure
Name it and configure options
User enters a column name (required). For select/multi-select columns: user adds option labels and picks a colour for each. For number: picks a prefix/suffix. Click "Add column" to confirm.
④ Column appears
Column is inserted immediately
The new column appears at the right end of the table. All existing rows show an empty cell. The column header is editable (click to rename). A column settings icon (⋯) appears on hover of the header — options: Rename, Edit options, Hide, Delete.
  • Reorder columns by dragging the header
  • Hide from this view without deleting data
  • Custom column data persists across all views
⑤ Inline editing
Values editable in the row
Custom column values are editable inline just like built-in columns. Click to edit. The edit interaction follows the field type: text box for Text, date picker for Date, dropdown for Select, toggle for Checkbox.
  • Tab key moves between custom fields
  • Enter to commit, Escape to cancel
  • Custom fields included in CSV export
Task detail

Task detail panel — the full picture

Clicking the ↗ icon on any task row opens a slide-in panel from the right — without navigating away from the list. This panel shows everything about a task.

📋
Core fields
Task name (editable heading), Status dropdown, Priority, Due date, Start date, Members, Client. All editable in the panel.
  • All built-in columns shown here
  • All custom columns shown in a Custom Fields section
  • Changes save immediately (no save button needed)
📝
Description & notes
A rich text description field below the core fields. Supports basic formatting: bold, italic, bullet lists, numbered lists, inline code. Not visible in the table view row.
  • Slash commands: /bullet, /heading, /code
  • Paste images directly into description
  • Link text supported
☑
Sub-tasks
A checklist of smaller tasks within this task. Each sub-task has a name, assignee and completion checkbox. Sub-task completion drives the progress bar in the table view.
  • Unlimited sub-tasks per task
  • Sub-tasks show in progress calculation: X/Y (P%)
  • Sub-tasks can have their own assignees
💬
Comments
A threaded comment section. Each comment shows author avatar, timestamp, and rich text. @mention to notify a team member. Replies supported.
  • @mention triggers in-app notification
  • Edit or delete own comments
  • Client users can comment if given access
📎
Attachments
File attachments linked to a task. Drag-and-drop to upload. Images shown as thumbnails. Other files as named links. Stored in Jiganto Files module.
  • Drag & drop or click to upload
  • Image preview thumbnails
  • Max 25MB per file (configurable)
⏱
Time tracking
A start/stop timer per task. Manual time entry also supported. Logged time feeds into the Timesheets module if connected.
  • Start timer with one click
  • Manual entry: add hours and description
  • Time log visible in task panel
